# Kivo README 与配图设计

日期：2026-08-04  
状态：已确认

## 目标

为 Kivo 补充一份以最终用户快速理解和上手为主、兼顾开发者构建与贡献的中文 README。README 必须基于仓库当前实现，准确说明实体按键设备、桌面 helper、Device Profile、Hardware Profile、Runtime Assignment、多设备并行和本地使用统计之间的关系。

README 同时提供真实应用界面截图和三张 Ian 小黑风格正文插图。实图负责展示产品本身，插图负责解释抽象关系，二者不互相替代。

## 非目标

- 不把 README 写成电话硬件改造手册。
- 不重复仓库内的长篇设计文档和历史迁移记录。
- 不承诺未经物理设备验证的平台或板卡能力。
- 不把 README 做成营销落地页、正式架构图或完整 API 参考。

## 目标读者与语言

主读者是准备下载、连接设备并配置按键动作的 Kivo 用户。次读者是需要在本地运行桌面端、构建固件或参与开发的工程师。

正文以简体中文为主。代码、命令、文件名和已经稳定的领域词保留英文，例如 Device Profile、Hardware Profile、Runtime Assignment、ESP32-S3 和 YD-RP2040。

## README 结构

1. `Kivo` 标题、一句话价值说明、下载入口和主视觉插图。
2. 核心能力：文字粘贴、快捷键、多设备独立分配、学习式硬件映射、本地统计、配置导入导出与备份。
3. 真实界面截图，让读者看到当前桌面应用而不是概念效果图。
4. 工作方式：实体输入经过设备固件、Runtime Assignment 和桌面 helper 后执行动作。
5. 快速上手：下载安装、连接设备、创建或导入配置、映射按键、分配设备、验证动作。
6. 支持硬件：LuatOS ESP32-S3-AIO 与 YD-RP2040 的构建、运行和上传入口。
7. 本地开发：精确 Node/npm 环境、Rust、uv、依赖安装、`make helper`、测试和构建。
8. 项目结构、关键命令和进一步文档入口。

README 的命令必须直接来自当前 `package.json`、`Makefile`、`platformio.ini`、`.nvmrc`、`.envrc` 和发布工作流。用户流程必须使用 `CONTEXT.md` 中的现行领域术语。

## 视觉设计

所有插图保存到 `assets/readme-illustrations/`，使用 16:9 横版 PNG，纯白背景、黑色手绘线稿、大量留白和少量红橙蓝中文批注。小黑必须承担核心动作，不能只是装饰。不得出现 PPT 信息图、商业矢量插画、复杂架构图、左上角类型标题、纸张纹理、阴影或渐变。

### 01 Kivo 主视觉

- 位置：标题与价值说明之后。
- 核心意思：实体按键可以通过 Kivo 变成文字粘贴和快捷键动作。
- 隐喻：小黑认真操作一台荒诞的老式插线台；卷线电话和实体按键从一侧接入，另一侧吐出文字纸条和快捷键闪电。
- 建议标注：`实体按键`、`Kivo`、`文字`、`快捷键`。

### 02 配置关系

- 位置：工作方式之后。
- 核心意思：按键布局、硬件接线和设备分配是三个相互配合但不同的层次。
- 隐喻：小黑转动套准钉，把三张形状不同的透明描图纸准确叠到一台实体设备上。
- 建议标注：`长什么样`、`怎么接线`、`交给哪台设备`、`开始工作`。

### 03 多设备并行

- 位置：多设备能力或支持硬件之后。
- 核心意思：ESP32-S3 和 YD-RP2040 可以同时在线，并保持各自的 Runtime Assignment。
- 隐喻：小黑给两台并排的怪唱机分别上弦；两张唱片沿各自轨道播放，最后汇入同一张本地计数表。
- 建议标注：`ESP32-S3`、`YD-RP2040`、`各跑各的`、`一起在线`。

真实界面截图保存到 `assets/readme/app-overview.png`。截图使用仓库的预览数据，不伪造硬件连接状态，不覆盖现有证据文件。
