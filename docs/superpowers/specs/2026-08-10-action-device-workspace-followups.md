# Action 与设备工作区问题清单

> 状态：代码、最新全量自动化、响应式视觉验收和 macOS 实机 Action 验证已完成；复杂 Paste、等待、播放/暂停、下一首、音量加减均有实体运行证据，`Previous` 未单独采样
>
> 目的：把当前 Action、按键行为编辑和设备管理页面中已经确认的问题集中记录，作为后续实现与验收的唯一清单。本文件补充 `2026-08-09-action-triggers-and-device-workspace-design.md`，不重新定义已经确认的配置文件和设备关系。

## 1. 已确认的产品关系

- **配置文件**是可导入、导出、复制和分享的同步载体，继续保留独立的配置文件管理页面。
- **设备管理**负责选择当前正在管理的设备，以及选择该设备实际使用的配置文件。
- 一个设备可以使用一个配置文件；多个设备可以共享同一个配置文件。
- 编辑配置文件时，如果它被多个设备使用，界面必须明确提示“修改会影响哪些设备”，并提供“保存共享配置”和“复制并仅用于此设备”两个明确选项。
- **按键行为**是一个独立页面：页面负责浏览全部按键及其 Action 对应关系；单个 Action 的内容编辑使用弹窗。
- **设备管理**是一个独立页面：I/O 映射和按键布局直接在页面工作区内编辑，不再放到弹窗里；设备设置弹窗只放触发阈值等紧凑设置和配置文件复制操作。
- 触发类型保留：`按下`、`释放`、`长按`、`双击`。不再单独提供“短按”；默认触发类型必须是“按下”。

## 2. 优先级

### P0：运行时必须正确

这些问题会直接导致用户配置后按键仍然无效，必须先于视觉优化完成。

#### 2.1 编辑后的 Action 没有自动保存或运行时仍使用旧值

现象：行为编辑页面改完内容后，界面看起来已经变更，但实际按键仍执行旧行为，或者刷新后修改消失。

要求：

1. 每次有效编辑都更新当前配置文件草稿，并进入统一的自动保存队列。
2. 保存成功后更新配置文件版本/快照，设备运行时收到同一份新快照。
3. 设备使用共享配置文件时，继续遵守显式的共享保存/复制确认，不得静默覆盖其他设备。
4. 保存状态必须可见：保存中、已保存、保存失败都要有明确状态；失败时保留草稿并允许重试。
5. 在保存完成前触发按键时，运行时不得悄悄回退到旧配置；应使用最后一个已确认有效的快照，并在界面说明当前保存状态。
6. 对 Action 内容、触发类型、按键布局和 I/O 映射的修改使用同一套保存与运行时更新路径，避免“有的编辑会生效、有的不会生效”。

验收：修改一个按下 Action，等待保存完成后立即按键，执行结果必须是新内容；重启应用后新内容仍存在；保存失败时不会破坏旧配置或丢失草稿。

#### 2.2 等待/延时 Action 不执行

现象：Action 序列中的等待（延时）没有真正阻塞后续 Action，或等待 Action 本身没有执行。

要求：

- 等待按毫秒执行，范围和校验沿用配置文件协议约束。
- 同一按键的一组 Action 必须保持顺序：前一个等待完成后才执行下一个 Action。
- 等待期间不能重复启动同一个运行；新的触发按设备既有的串行队列规则处理。
- 日志/活动记录要能区分“开始等待”“等待完成”和“等待失败”。

验收：配置“粘贴 A → 等待 500ms → 媒体播放/暂停”，可观察到至少 500ms 的间隔，且后续 Action 仍执行。

#### 2.3 媒体控制 Action 不生效

现象：媒体播放/暂停、下一首、上一首等 Action 被保存，但 macOS 上没有产生对应控制效果。

要求：

- 明确并统一媒体命令枚举，前端选择值、持久化值和运行时值不能各用一套名字。
- macOS 运行时发送系统可识别的媒体控制事件；失败时返回结构化错误并展示在设备活动记录中。
- 媒体 Action 与快捷键/粘贴/等待一样进入同一条运行队列，不能因为不是键盘字符而被跳过。

验收：在 macOS 上分别验证播放/暂停、下一首、上一首（以及当前支持的其他命令），每一种命令都能在活动记录中看到开始、完成或明确失败原因。

#### 2.4 粘贴 Action 不写剪贴板或没有执行

现象：macOS 上粘贴文本 Action 既没有执行，也没有把文本写入系统剪贴板；重新刷固件后问题仍存在，因此不能只归因于固件版本。

要求：

- 主机先以 UTF-8 文本写入系统剪贴板，再发送粘贴快捷键；文本不能直接依赖键盘字符输入。
- 写剪贴板失败、发送粘贴快捷键失败、设备未连接等情况分别报告，不能统一吞成“Action 无效”。
- 写入剪贴板和粘贴触发都要有可追踪的运行日志，并注明设备、按键、Action 和运行 ID。
- 在 macOS 上验证应用权限（辅助功能/自动化）不足时，错误提示要告诉用户缺少哪项权限以及如何处理。

验收：输入包含中文、换行和符号的文本，确认剪贴板内容正确、目标应用最终收到文本；权限不足时能看到可操作的错误，而不是静默失败。

### P1：行为编辑器交互

#### 2.5 控制键名称不能被翻译成含义不明的本地化词

现象：快捷键选择器把 `Command`、`Control`、`Option/Alt` 等技术键名翻译后，用户无法确认实际发送的是哪一个键，左右侧也容易混淆。

要求：

- 物理/协议键名保持稳定显示：`Left Command`、`Right Command`、`Left Alt`、`Right Alt`、`Left Control`、`Right Control`、`Left Shift`、`Right Shift` 等不得被替换成含义不明确的中文词。
- 分类标题、辅助说明可以本地化，但具体键 token 必须保留英文技术名和左右方向。
- 同一个 token 在已选列表、分类列表、录制结果、Action 摘要和运行日志中使用同一显示规则。
- macOS 常用缩写可作为补充信息，但不能隐藏完整的左右键名。

#### 2.6 录制快捷键入口必须在上方

现象：录制快捷键按钮藏在很长的键列表底部，用户必须滚动到底才能找到。

要求：

- “录制快捷键”放在快捷键 Action 的上方，与已选键、搜索框处于同一操作区。
- 录制中、录制完成、录制取消和录制失败都要有即时状态反馈。
- 录制结果必须经过同一套重复键、最多六个普通键和左右修饰键校验。
- 手动选择和录制产生的结果使用同一数据结构，不允许录制路径绕过校验。

#### 2.7 快捷键分类必须使用 tab 和单一按键列表

现象：当前快捷键选择器把“常用、功能键、字母、数字、符号、导航、数字小键盘”七组内容从上到下全部展开，弹窗非常长；分类只是分组标题，不能像正常 tab 一样切换。

目标结构：

```text
快捷键 Action 弹窗
├─ 已选按键与录制快捷键
├─ 搜索按键
├─ 修饰键（可展开左右侧）
└─ 分类 tab
   ├─ 常用 | 功能键 | 字母 | 数字 | 符号 | 导航 | 小键盘
   └─ 当前 tab 对应的单一按键列表
```

要求：

- 分类使用一个可键盘操作的 `tablist`，每次只有一个 tab 被选中。
- 切换 tab 后只渲染该分类的按键详情列表，不再同时堆叠七个分类。
- 默认选中“常用”；搜索只过滤当前分类，并保留当前 tab 和已选按键。
- 当前 tab、已选按键和禁用的第七个普通键都要有清晰状态。
- 修饰键保持在分类 tab 上方，左右 Command/Control/Alt/Shift 仍可多选。
- 单个 Action 的字段编辑仍然使用弹窗；按键与全部 Action 的对应关系仍然属于独立的按键行为页面。
- 小屏幕下 tab 可以横向滚动，按键列表减少列数，但弹窗本身不能横向溢出。

### P1：设备管理页面布局与按钮

#### 2.8 设备管理必须是“左窄右宽”的工作区

现象：设备列表占据主要宽度，右侧详情和 I/O/布局编辑区被压缩；与预览中“窄设备表 + 大工作区”的关系相反。

要求：

- 桌面端使用两列：左侧约 `320–380px` 的设备列表，右侧占用剩余全部空间。
- 左侧表格列使用省略显示，设备名、型号、状态、运行分配仍可扫描；不能因长文本撑宽列表。
- 右侧设备详情、配置文件选择、I/O 映射和按键布局获得主要空间。
- 设备列表、候选设备和右侧工作区各自滚动，不能让整个页面出现无意义的横向滚动。
- `900px` 以下继续上下堆叠：先列表，后详情；移动端不丢失操作入口。

#### 2.9 所有业务按钮必须使用统一设计系统

现象：保存运行分配、清除运行分配、配置设置、共享配置、应用硬件配置和设置弹窗底部按钮退回浏览器原生灰色按钮，和其余页面不一致。

要求：

- 业务按钮统一使用现有按钮基础样式：边框、圆角、背景、阴影、hover、disabled、focus-visible 状态一致。
- 主操作使用绿色 `primary-button`；危险操作使用红色 `danger-button`；普通操作使用统一次要按钮样式。
- “配置设置”“保存共享配置”“复制并仅用于此设备”等按钮要有明确层级，不得全部显示成同样的原生按钮。
- 图标按钮继续使用图标、可访问名称和 tooltip；不把文字命令伪装成图标按钮。
- 选项卡、设备过滤器和表格行是专用控件，不能被通用按钮样式破坏。

验收：在 1120px、1440px 和 390px 视口截图中，不得出现浏览器默认按钮外观；hover、disabled、键盘 focus-visible 均可辨认。

#### 2.10 工作区版本不兼容不能导致 macOS 启动崩溃

现象：已安装的 Kivo `0.5.1` 读取由较新开发版本写出的 Device Profile schema 时，`Workspace::load` 返回 `unsupported_profile_schema`。错误继续穿过 Tauri `setup` 回调后，在 macOS `did_finish_launching` 中触发不可 unwind 的 Rust panic，最终产生 `SIGABRT`。

要求：

- 所有应用初始化错误必须在 Kivo 的启动边界内被消费，不能返回给 Tauri 的 macOS 启动回调。
- 工作区加载前先安装运行日志；失败时写入 `application_startup_failed` 和稳定错误码。
- schema 较新时不得降级、重置或覆盖配置，也不得构造一个看似可编辑的假工作区。
- 主窗口只显示阻断式启动失败页，明确说明需要更新 Kivo、现有配置未被修改，并显示稳定技术错误码。
- 启动失败页不得调用 `get_snapshot`、订阅设备运行事件或启动配置自动保存。
- 有效 schema 的窗口、菜单栏和托盘初始化路径保持不变。

验收：release macOS 构建在有效 schema 下进入 `application_ready`；在未来 schema 下冷启动和重复启动均不 panic、不生成新的 `.ips` 报告，并显示 `unsupported_profile_schema` 兼容性页面。

## 3. 实现顺序

1. **运行时正确性**：自动保存与运行时快照更新、等待、媒体、粘贴及错误日志。
2. **行为编辑器结构**：保持按键与 Action 的独立页面关系和单 Action 弹窗边界。
3. **快捷键选择器**：稳定技术键名、分类 tab、左右修饰键、顶部录制入口和录制状态。
4. **设备管理布局**：左窄右宽、表格省略、响应式堆叠。
5. **统一按钮视觉**：补齐所有设备管理和设置弹窗业务按钮的样式与状态。
6. **回归与视觉验收**：功能测试、构建、桌面/移动端截图和 macOS 实机动作验证。

## 5. 不在本次问题整理中重新讨论的内容

- 配置文件是否继续存在：已确认保留，作为分享/导入/导出的载体。
- 是否保留“短按”：已确认移除，默认使用“按下”。
- I/O 映射和按键布局是否弹窗：已确认放在设备管理页面内。
- 单个 Action 是否独立弹窗：已确认保留弹窗；Action 与按键对应关系仍是独立页面内容。
