# Kivo OLED 单行自适应渲染设计

日期：2026-08-11

状态：设计已确认

## 目标

当 `SSD1306 128x32` 画面只有一个非空视觉行时，合并该行内容，选择能够完整容纳
文本的最大内置等宽字体，并在全屏内居中显示。两行画面保持现有紧凑布局。

例如无待处理输入的运行汇总由当前分区画面：

```text
CODEX          3 RUN
```

改为单行大字画面：

```text
 CODEX 3 RUN
```

`CODEX` 与 `3 RUN` 之间只保留一个 ASCII 空格，消除当前两个 64px region 造成的
大段空白。

## 单行判定与布局

Renderer 先生成语义上的首行左右文本和第二行文本，再按以下规则排版：

1. 首行左右文本去除空项后，以一个空格连接为一个视觉行。
2. 首行与第二行中恰好只有一个非空视觉行时，使用单行全屏布局。
3. 两个视觉行均非空时，继续使用现有三个稳定 region 和 `6x13` 字体。
4. 单行布局使用一个 `128x32` region；文本水平居中，baseline 使用该字体的固定
   垂直居中值。

单行字体按能否完整落在 128px 宽度内依次选择：

| Font ID | U8g2 字体 | 字符 advance | Baseline | 使用条件 |
| --- | --- | --- | --- | --- |
| `2` | `u8g2_font_10x20_tf` | 10px | 22px | 文本宽度不超过 128px |
| `1` | `u8g2_font_9x18_tf` | 9px | 21px | 10x20 放不下且该字体能放下 |
| `0` | `u8g2_font_6x13_tf` | 6px | 21px | 更长文本的兼容回退 |

Renderer 根据 ASCII 字符数计算固定宽度和居中 `x`。现有文案最长 16 字符，因此
最后一级能够完整显示，不新增滚动、缩写或截断行为。

## 协议兼容

- 基础远程显示协议仍从 v7 可用，v7 设备继续收到当前 `font_id=0` 的三 region
  画面，不丢失 Codex 状态显示。
- Host 与新固件协议版本提升到 v8，并新增大字体能力常量。
- 只有协议 v8 设备使用单行自适应 Renderer；Host 不会向 v7 固件发送 font ID 1
  或 2。
- Host 编码器和固件解析器接受 font ID 0、1、2；RP2040 绘制层按 ID 映射到上述
  U8g2 字体。ESP32-S3 的无 OLED 路径保持不变。
- OLED 配置本身的最低协议版本不变；没有 OLED 的设备行为不变。

## 增量刷新

单行布局使用一个全屏 region。三 region 与单行 region 之间切换时，region bounds、
字体或文本均进入 content hash，SceneTracker 会发送覆盖完整 128x32 范围的变化，
避免旧字号像素残留。单行内计数变化仍只产生一个 region 更新。

## 测试与验收

自动化测试覆盖：

- `CODEX 3 RUN` 合并为 `CODEX 3 RUN`，使用 `10x20`、全屏 region 和居中坐标。
- 较长计数选择 `9x18`，超出该宽度时回退 `6x13`。
- 有 `NEEDS INPUT` 的两行汇总保持现有三个 region、字体和 baseline。
- v7 连接继续生成旧布局，v8 连接生成自适应布局。
- Host 只接受 font ID 0、1、2，固件拒绝其他 ID。
- RP2040 绘制层对三个 font ID 使用正确 U8g2 字体。
- 单行与两行场景互换时，全屏范围进入 dirty tiles。
- 完整 Rust、native firmware 和 RP2040 构建通过。

自动化只能证明布局指令、协议和编译结果。最终真机验收仍需观察单行字体的实际
居中、可读性、字符间距和画面切换残影。

## 非目标

- 不修改两行状态的内容优先级或文案。
- 不增加 CJK 字库、图标、动画或滚动文本。
- 不让固件猜测 Codex 语义或自行合并 region。
- 不改变 OLED 接线、Device Profile YAML 或面板旋转规则。
