# Kivo Helper 普通用户体验设计

日期：2026-08-13

## 背景

Kivo 已具备设备发现、首次配置、按键行为、按键布局、I/O 映射、配置文件管理、自动保存和运行状态等完整能力，但当前界面按内部数据模型组织。普通用户需要在“设备管理”“按键行为”“配置文件”“硬件配置”等概念之间切换，才能完成最常见的任务：插入一个键盘并修改某个按键的功能。

本设计重新组织前端体验，不改变现有设备身份、配置文件、Hardware Profile、Runtime Assignment、协议或持久化模型。默认界面服务普通用户，高级能力仍保留，但不再占用日常主流程。

本设计取代以下旧设计中的用户界面组织方式，但保留其领域约束和数据一致性要求：

- `2026-08-01-device-onboarding-and-profile-creation-design.md`
- `2026-08-09-action-triggers-and-device-workspace-design.md`
- `2026-08-10-action-device-workspace-followups.md`

## 目标

- 用户插入设备后，不理解配置 ID、板型、串口、I/O 或 Runtime Assignment 也能完成设置。
- 已配置用户打开 Kivo 后直接看到当前键盘，一次点击即可开始修改按键。
- 多设备切换只需要一次操作。
- 日常界面只展示当前任务所需的信息；低频和专业能力有稳定、可发现的入口。
- 所有有效修改自动保存，并明确展示保存、离线和错误状态。
- 保留现有配置和高级编辑能力，不进行数据迁移或功能删减。

## 非目标

- 不修改后端 Workspace schema、设备协议或固件。
- 不取消 Device Profile、Hardware Profile 或 Runtime Assignment；这些概念只是不再直接暴露给普通用户。
- 不在本次重新设计 Action 类型、触发语义、快捷键选择器或 I/O 学习协议。
- 不把 Kivo 改造成营销首页、数据仪表盘或移动端应用。
- 不用“简单模式 / 高级模式”开关制造两套会变化的界面状态。

## 设计原则

1. **设备优先**：普通用户面对的是一块键盘，不是一个配置文件。
2. **下一步明确**：每个状态只突出当前最需要做的一件事。
3. **默认自动化**：能从设备和现有配置推断的字段自动选择，不要求用户理解内部关系。
4. **渐进展开**：按下行为优先，长按、双击、布局和 I/O 在需要时再出现。
5. **状态可恢复**：离线、失败或取消不会丢失已有配置，也不会阻塞其他设备。
6. **共享修改不意外扩散**：简化界面不能绕过多个设备共享配置时的影响确认。

## 信息架构

### 顶部栏

顶部栏包含：

- Kivo 品牌；
- 当前设备切换器；
- 当前设备连接状态；
- 全局保存状态。

设备切换器显示用户命名的物理键盘，而不是 Device Profile。在线设备排在前面，离线设备继续可选。切换设备后，“我的键盘”和“设备”页面都使用同一目标，避免不同页面分别维护难以理解的选择。

只有一台设备时仍显示设备名称和状态，但弱化下拉箭头；没有设备时显示“连接键盘”。

### 侧栏

默认侧栏仅保留三个带文字的入口：

1. **我的键盘**：默认首页和日常按键编辑入口。
2. **设备**：连接状态、添加、重命名、移除和设备级故障处理。
3. **设置**：语言、备份等低频应用设置，以及页面底部的“高级设置”入口。

不使用仅图标导航。原“首页统计”和独立“按键行为”入口移除：按键行为并入“我的键盘”，统计成为设备页的次要内容。

### 设置与高级设置

设置页保持短而稳定，不直接展开专业字段。页面底部提供清晰的“高级设置”入口。高级设置包含：

- 按键布局；
- I/O 映射；
- 配置文件创建、复制、导入、导出和删除；
- 设备板型、固件、端口、协议等技术信息。

高级设置是一个可返回的独立工作区，不是改变整个应用的模式开关。进入或退出不会改变数据、默认首页或以后启动时的界面。

## 状态驱动的默认首页

应用启动后根据当前设备状态决定“我的键盘”内容：

- **无设备**：显示连接键盘的空状态，并持续自动检测。
- **发现新设备**：自动打开首次设置向导。
- **设备待配置**：显示“继续设置”主操作；用户关闭过向导后不重复强制弹出。
- **设备已就绪**：显示可点击键盘和右侧编辑面板。
- **设备离线**：保留键盘和编辑能力，顶部标记“未连接”；只禁用需要实体设备的测试或学习操作。
- **设备异常**：显示用户能理解的问题和一个优先修复动作，技术详情折叠。

应用记住上次选择的物理设备。若该设备不存在，则优先选择在线且已就绪的设备，其次选择在线待配置设备，最后选择离线设备。

## 首次设置向导

发现新的在线 Candidate 或在线未分配 Device 时，沿用现有一次性自动打开规则，显示聚焦的三步向导。

### 第一步：识别设备

显示：

- 用户可理解的设备名称；
- 可选的布局外观缩略图；
- “已找到你的键盘”状态；
- 软件推荐的设备预设。

不显示完整序列号、板型 ID、串口或协议。无法完成识别时显示“重新检测”，并把原始信息收进“技术详情”。

### 第二步：选择预设

根据 Board Profile 和兼容 Hardware Profile 自动筛选可用配置：

- 有唯一明确匹配时默认选中，用户通常只需继续；
- 有多个合理匹配时，用布局名称和外观预览让用户选择；
- 没有匹配时提供“创建新键盘设置”，其默认布局和 ID 由软件生成；
- “手动配置硬件”只作为高级入口出现。

主流程不出现“键盘配置”“硬件配置”或“运行分配”等内部术语。

### 第三步：测试按键

显示完整键盘预览，提示用户按下几枚代表性按键。设备事件到达时对应按键即时高亮。测试的目的只是确认设备和所选布局可用，不要求用户逐键完成映射。

提供：

- “完成设置”；
- “跳过测试”；
- 测试失败时的“重新检测”；
- 进入高级 I/O 设置的次级入口。

每一步都可以“稍后设置”。关闭后不回滚已经成功创建的配置；设备页保留“继续设置”。完成时继续使用现有原子设备名称与 Runtime Assignment 写入边界。

## 我的键盘

### 页面布局

页面由两个稳定区域组成：

- 中间主区域展示当前物理键盘的布局；
- 右侧固定面板编辑当前按键。

键盘区域不会因选择按键或切换 Action 类型而改变尺寸。默认选中上次编辑的按键；没有记录时选中第一个按键。实体按键输入仍可在界面中高亮，但不会意外改变编辑目标。

### 按键呈现

每个按键优先显示用户名称，技术 ID 仅以弱化的小字显示。按键状态包括：

- 未选中；
- 当前选中；
- 实体按下；
- 未设置；
- 有多个行为。

未设置按键显示“未设置”，点击后直接进入常用功能选择，不显示空白编辑器。

### 右侧编辑面板

面板顶部显示“当前按键”和可直接编辑的按键名称。下方按触发类型展示行为：

- 默认首先展示“按下时”；
- 已配置的释放、长按和双击行为直接显示；
- 未配置的高级触发通过“添加其他行为”展开；
- 每条 Action 使用简短、可扫描的摘要，点击后复用现有 Action 弹窗；
- 新建 Action 优先展示常用功能：复制、粘贴、快捷键、打开应用、输入文字和媒体控制；完整类型仍可访问。

普通编辑没有“保存”按钮。每次合法变更进入现有统一自动保存队列。顶部只显示“保存中”“已保存”或“保存失败 · 重试”。Action 弹窗继续使用明确的保存和取消，因为它需要维护一份未完成的本地草稿。

### 多设备共享配置

当当前设置只被一台设备使用时，修改直接自动保存。

当配置被多台设备共享时，第一次尝试修改前显示一次影响选择：

- **仅修改这台键盘**（推荐）：原子复制完整配置、分配给当前设备，然后继续应用本次修改；
- **同步修改所有共用键盘**：继续编辑共享配置，并明确列出受影响设备数量。

选择在当前设备和当前配置关系不变期间保持有效。关系变化后再次确认。复制或保存失败时保持原分配和原配置，保留用户草稿并显示重试，不允许静默影响其他设备。

## 设备页

设备页从专业工作区收敛为状态和管理页面：

- 当前设备概要；
- 连接、离线、待设置或需要处理的状态；
- 重命名；
- 添加键盘；
- 继续首次设置；
- 忘记设备；
- 次要的按键次数和近期活动。

板型、固件构建、完整序列号、端口和 Runtime Assignment 默认不显示，统一进入“技术详情”或高级设置。布局和 I/O 编辑器不再作为设备页的常驻 tab，而由高级设置承载。

## 错误与恢复

错误文案固定使用“发生了什么 + 下一步做什么”的结构：

- **未连接**：保留可编辑内容，提示重新连接设备。
- **固件未响应**：提供“重新检测”，建议重新插拔或关闭占用设备的软件。
- **固件不兼容**：提示更新 Kivo 或设备固件，不在主文案暴露协议版本。
- **端口被占用**：提示关闭可能占用键盘的软件后重试。
- **身份无效或冲突**：不允许绕过校验绑定，提示只保留用户可执行的排查动作。
- **自动保存失败**：保留本地草稿，顶部持续显示失败状态和重试操作。
- **设备在向导中断开**：保留当前步骤；同一设备重新连接后继续。
- **一个设备异常**：不阻塞其他设备的切换、编辑和保存。

原始错误码、完整身份、端口和协议详情始终可在技术详情中查看，便于支持和调试。

## 前端组件边界

本设计优先组合和收敛现有组件：

- `App`：统一当前物理设备选择、顶栏状态和页面导航。
- 新的日常键盘工作区：组合现有 `Keypad` 与 `ActionEditor`，取代统计型 `HomeDashboard` 作为默认首页。
- `ActionEditor`：保留 Action 分组和弹窗边界，调整为空状态、常用入口和右侧面板呈现。
- `DeviceSetupWizard`：保留现有 Candidate/Device 状态驱动与命令回调，改成三步普通用户流程。
- `DeviceManagement`：收敛为设备状态与管理；高级编辑能力移动到高级设置容器。
- `LayoutEditor`、`HardwareMapping` 和配置文件管理：复用现有实现，通过高级设置访问。

不复制业务状态到新的平行模型。设备、配置和运行分配仍以 `AppSnapshot` 为权威；未完成的表单和 Action 草稿继续只在组件本地存在。

## 响应式行为

桌面端保留“键盘主区域 + 右侧编辑面板”。窄窗口下：

- 侧栏变为顶部或底部的三项文字导航；
- 设备切换器保持可见；
- 右侧编辑面板移动到键盘下方，不覆盖按键；
- 键盘按现有分组和列数缩放，不产生水平滚动；
- Action 弹窗、首次向导和高级设置不得超出视口；
- 所有文本按钮允许换行，技术 ID 使用截断或换行，不挤压主操作。

## 测试设计

### React 行为测试

- 启动时按照无设备、待配置、就绪、离线和异常状态显示正确首页。
- 设备切换器切换物理设备后，键盘、编辑面板和状态同步更新。
- 已就绪设备打开后默认显示键盘，点击按键后右侧面板更新。
- 未设置按键直接进入常用功能选择。
- 合法名称和 Action 修改进入统一自动保存；失败保留草稿并可重试。
- 共享配置第一次修改时必须选择影响范围；独立复制失败不改变原配置和分配。
- 新 Candidate 只自动弹出一次向导，关闭后可从设备页继续。
- 三步向导按权威 Candidate/Device 状态前进，拔出和重新插入可恢复。
- 普通页面不出现配置 ID、Hardware Profile、Runtime Assignment 或端口文案。
- 高级设置仍可访问布局、I/O、配置文件和技术详情。

### 现有契约回归

- Candidate 在 HELLO 校验通过前不能绑定。
- 配置创建与最终绑定仍是独立事务。
- Runtime Assignment 必须精确匹配兼容 Hardware Profile。
- Action 触发语义、自动保存队列和运行时快照更新保持不变。
- 导入、导出、备份、恢复、复制和删除能力保持可用。
- 多设备命令继续携带精确 Device ID，不按当前视图或板型扇出。

### 视觉与可访问性验收

在桌面和窄窗口验证：

- 侧栏只有三个清晰文字入口；
- 顶部设备切换器和保存状态不互相挤压；
- 键盘与编辑面板无重叠、无跳动；
- 向导每一步只有一个明确主操作；
- 空状态、离线、错误和保存失败均可辨认；
- 键盘导航、焦点状态、dialog 语义、tab 顺序和屏幕阅读器名称完整；
- 390px、1120px 和 1440px 视口无页面级横向溢出。

### 完整验证

- 前端聚焦测试与完整 Vitest；
- TypeScript 和 Vite production build；
- Rust、runtime smoke 和 firmware 测试保持通过；
- `git diff --check`；
- 浏览器截图和像素检查；
- macOS 实机完成“连接设备 → 三步设置 → 修改一个按键 → 自动保存 → 实体按键执行”的端到端验收。

## 成功标准

1. 新用户从插入设备到设置第一个按键，不需要理解配置 ID、板型、I/O、串口或 Runtime Assignment。
2. 已配置用户打开 Kivo 后直接看到上次使用的键盘，一次点击即可开始编辑按键。
3. 多设备切换只需使用一次顶部选择操作。
4. 单设备编辑自动保存；共享配置不会在未经确认时影响其他设备。
5. 设备离线或保存失败时不丢失可编辑内容，且用户始终知道下一步。
6. 所有现有配置、高级编辑和数据管理能力仍可访问且行为不变。
