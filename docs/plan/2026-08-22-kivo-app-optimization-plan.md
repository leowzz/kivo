# Kivo App 优化方案

- 日期：2026-08-22
- 状态：方案草案，供产品、交互与工程评审
- 依据：[`kivo-ui-interaction-competitive-research.md`](../research/kivo-ui-interaction-competitive-research.md)
- 适用范围：Kivo 桌面端 React UI、向导、设备工作区、动作编辑、学习与测试体验
- 关系：本方案补充并更新 [`ux-consumer-optimization-plan.md`](../ux-consumer-optimization-plan.md)；不替代领域模型、固件协议和已确认的运行时约束

## 1. 结论先行

Kivo 的默认体验应从“管理配置文件”改成“直接编辑我手上的设备”。用户插入设备后，第一屏就看到设备、真实按键布局和当前按键动作；第一次成功不是“完成一个配置表单”，而是“按一下实体键，电脑得到预期结果”。

产品方向可以概括为：

> **像 Stream Deck 一样编辑，像 Options+ / Wootility 一样上手，像 Ableton Mapping 和 VIA Key Tester 一样学习与验证；技术能力仍保留，但默认不要求用户理解技术领域模型。**

本方案优先解决四个问题：

1. 从配置对象出发，改为从设备任务出发。
2. 从“选择 Profile 并分配”出发，改为“插入、选用途、按键验证”。
3. 从“添加动作弹窗”出发，改为可搜索、可浏览、可复用的动作库。
4. 从“自动保存即结束”出发，补上学习、测试、撤销和恢复闭环。

## 2. 设计目标与边界

### 2.1 目标

- 新用户在连接完成后 90 秒内完成第一个“粘贴文本”或“快捷键”动作，并通过实体按键验证。
- 普通用户无需理解 `Device Profile`、`Hardware Profile`、`Runtime Assignment`、GPIO、矩阵和端口。
- 设备的实体输入、画布位置、动作摘要和运行结果始终能互相对应。
- 成品设备和 DIY 控制器共用一套应用能力，但复杂度按模式和上下文隔离。
- 所有重要改动可撤销、可复制、可恢复；自动保存不再意味着误改不可逆。
- 现有身份校验、设备独立分配、共享配置语义和固件协议不被 UI 简化破坏。

### 2.2 非目标

- 不重写 `Device Profile`、`Hardware Profile` 或 `Runtime Assignment` 数据模型。
- 不在本阶段引入插件商店、账号、云同步或复杂自动化语言。
- 不用 3D 设备资产替代所有 DIY 布局；二维布局和 SVG 足以覆盖首版。
- 不把统计卡片作为默认首页，也不为了视觉变化重做现有 token 体系。
- 不把一键刷机作为本方案的前置条件；刷机体验可按旧 UX 方案另行排期。

## 3. 用户心智模型

默认界面只需要用户理解三个对象：

| 用户语言 | 对应实现 | 用户要回答的问题 |
| --- | --- | --- |
| 我的设备 | `Device` | 我现在在编辑哪一块实体设备？ |
| 按键 | `ModelButton` / 布局 | 我手上的哪个键？ |
| 动作 | `ButtonAction` | 按下后电脑会做什么？ |

以下概念继续存在，但默认隐藏或自动完成：

| 技术对象 | 默认策略 | 进入条件 |
| --- | --- | --- |
| `Device Profile` | 对外称“键盘设置”或“场景” | 复制、导入、共享配置时显示 |
| `Hardware Profile` | 自动选择兼容接线方案 | 冲突、学习或创客模式 |
| `Runtime Assignment` | 自动完成并以“正在使用”表达 | 设备修复、改绑和诊断 |
| Board Profile / GPIO / 矩阵 / 去抖 | 默认不出现 | “创客模式”或“技术详情” |

## 4. 信息架构

### 4.1 默认结构

默认进入设备工作区，侧栏不再把统计和配置文件当作首要任务：

```text
Kivo
├─ 我的设备                         设备列表与当前工作区
│  ├─ [设备 A]                       在线 / 需要设置 / 未连接
│  └─ [设备 B]
├─ 工作区标签                        当前设备内的任务视图
│  ├─ 按键                          默认视图：布局 + 动作
│  ├─ 测试                          实体输入测试与输出验证
│  └─ 活动                          使用记录与设备洞察
└─ 设置
   ├─ 成品模式 / 创客模式             渐进披露开关
   ├─ 数据与备份                     导入、导出、快照、恢复
   └─ 技术详情                       诊断字段和运行日志
```

现有 `App.tsx` 的 `view === "devices"` 继续作为默认入口；`view === "data"` 保留，但移动到设置下的“数据与备份”。统计不删除，改为当前设备的“活动”标签或侧栏二级入口。

### 4.2 成品模式与创客模式

成品模式是默认模式，面向购买后直接使用的用户：

- 设备、按键、动作、模板、测试、活动。
- 设备异常只展示下一步操作，不直接暴露错误码和引脚。
- 只展示“按下时”动作；长按、双击、释放放入“更多触发方式”。

创客模式面向 DIY 用户和调试人员：

- 布局编辑、接线学习、GPIO / 矩阵、显示屏、编码器、去抖、固件诊断。
- 允许选择具体 Hardware Profile，但必须始终绑定到明确的设备和配置。
- 不复制第二套应用，只在现有 `DeviceManagement` 工作区增加模式和技术标签。

模式切换是显式用户设置，不根据设备类型偷偷改变；切换后保留当前设备和选中按键。

## 5. 核心工作区

### 5.1 桌面布局

默认工作区采用左窄、中间布局、右侧动作的稳定三栏结构：

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ Kivo   我的设备 / Workbench One       已连接   已保存        测试  设置     │
├──────────────┬───────────────────────────────┬─────────────────────────────┤
│ 我的设备     │ 当前设备：Workbench One        │ 按键动作                    │
│              │ [重命名] [复制设置]             │ 3 号键 · “粘贴会议链接”       │
│ ● Workbench  │                               │                             │
│   One        │        ┌──┐ ┌──┐ ┌──┐          │ [搜索动作]                   │
│ ○ 电话终端   │        │1 │ │2 │ │3 │          │ 最近使用 / 文字 / 快捷键       │
│              │        └──┘ └──┘ └──┘          │                             │
│ + 添加键盘   │        ┌──┐ ┌──┐ ┌──┐          │ ┌─────────────────────────┐ │
│              │        │4 │ │5 │ │6 │          │ │ 粘贴文本                 │ │
│              │        └──┘ └──┘ └──┘          │ │ 粘贴“会议链接”           │ │
│              │                               │ └─────────────────────────┘ │
│              │       [按一下实体键验证]       │ [+ 添加动作]                 │
└──────────────┴───────────────────────────────┴─────────────────────────────┘
```

布局规则：

- 左栏约占 220–280px，只承担设备选择和异常提示；设备多时独立滚动。
- 中栏是主导航对象，按键画布维持稳定尺寸和真实布局比例。
- 右栏在选中按键后显示动作库与动作检查器；未选中时显示“选择一个按键开始”。
- 顶栏只保留当前设备、连接异常、保存状态和当前模式；正常连接状态不在三处重复展示。
- `900px` 以下变成列表 → 画布 → 动作面板的纵向布局；`390px` 仍可选择按键、添加动作和测试。

### 5.2 按键画布

- 画布是设备工作区的主对象，而不是配置文件表格的预览。
- 选中键显示清晰焦点、动作数量和第一条动作摘要。
- 实体按下时，对应画布键高亮；运行失败时只在该键显示局部错误状态，同时在活动中留下详情。
- 支持键盘方向键移动焦点，`Enter` 打开动作面板，`Escape` 返回设备选择。
- 布局调整只在创客模式或“按键布局”标签中进行，避免普通用户误拖动改变物理语义。

### 5.3 动作库与检查器

右侧动作区分成两个明确状态，而不是所有内容都塞进一个弹窗：

1. **动作库**：搜索、分类、最近使用、常用模板，支持点击添加和拖拽添加。
2. **动作检查器**：编辑已添加动作的字段、顺序和触发方式。

首版分类固定为：

| 分类 | 动作 | 卡片摘要示例 |
| --- | --- | --- |
| 文字 | 粘贴文本 | 粘贴“会议链接” |
| 快捷键 | 快捷键 | `Command + Shift + 4` |
| 打开 | 打开目标 | 打开 `https://...` |
| 媒体 | 播放、音量、下一首等 | 音量增大 |
| 流程 | 等待 | 等待 0.5 秒 |

动作卡片要求：

- 显示图标、自然语言摘要和触发位置，不只显示协议字段。
- 点击卡片直接加入当前“按下时”序列；“编辑”再打开已有 `ActionDialog`。
- 序列支持拖动排序，并保留上移、下移按钮作为键盘可达的备用操作。
- 长序列允许折叠单个动作；保存状态不挤压动作内容。
- 空状态给出三个常用模板，例如“粘贴一段文字”“打开网址”“发送快捷键”。

### 5.4 触发方式的渐进披露

主界面默认只显示：

```text
按下时
  [动作 1] → [动作 2]

更多触发方式 ▸
  释放时
  长按（0.5 秒）
  双击（0.3 秒）
```

只有用户展开“更多触发方式”后，才显示 `release`、`long_press`、`double_press` 和阈值设置。内部继续使用现有四种 `ActionTrigger`，不新增“短按”概念。

## 6. 首次连接与首次成功

### 6.1 三步向导

向导面向“完成一次有用动作”，而不是完成技术配置：

1. **识别键盘**：自动识别设备，用户只需要给它起名。
2. **选择用途**：选择一个模板或“从空白开始”；兼容 Hardware Profile 自动选择。
3. **按一下验证**：自动写入一个示例键，提示用户按实体键，输出成功后结束。

界面中不出现 `Device Profile`、`Hardware Profile`、`Runtime Assignment` 下拉框。存在多个兼容方案时默认选择一个，并在“接线方案（高级）”折叠区允许更换。

### 6.2 模板

首版提供 3 个用途模板，模板只是现有 Device Profile 的用户入口，不新增模板数据模型：

- **日常快捷键**：粘贴文本、打开网址、常用系统快捷键。
- **创作工作台**：复制、粘贴、撤销、媒体控制和等待动作。
- **电话终端**：数字按键、确认、常用号码或文本片段。

模板选择必须同时出现在：无设备首页、添加键盘向导、空白布局的动作区。用户可随时将模板复制为当前设备专用设置。

### 6.3 向导状态机

```text
发现设备
  ├─ 正在确认 → 已识别 → 命名
  ├─ 固件未响应 / 不兼容 / 引导模式
  │     ├─ 重新检测
  │     ├─ 先创建键盘设置
  │     └─ 查看技术详情
  └─ 身份冲突 / 无效身份 → 只显示消歧指引

命名 → 选择用途 → 自动分配 → 写入示例键 → 等待实体输入
                                      ├─ 成功：进入工作区
                                      ├─ 超时：重新按键 / 进入测试
                                      └─ 冲突：显示具体按键并允许修复
```

候选设备仍必须通过后端身份和 HELLO 校验，前端不得根据串口路径伪造已登记设备。配置创建和设备绑定保持两个可独立完成的持久化动作。

## 7. 逐键学习与测试模式

这是 Kivo 的辨识度功能，应从高级面板提升为独立模式。

### 7.1 学习模式

进入学习模式后，顶栏显式显示“正在学习”，并锁定当前设备和 Hardware Profile：

```text
自动识别按键                                     7 / 18
请按下画布高亮的实体键：按键 8

[布局画布]
已完成  1  2  3  4  5  6      当前  8      待完成  9 ...

[撤销上一步]  [跳过]  [结束学习]
```

规则：

- 画布先高亮目标键，用户按实体键后再确认物理输入。
- 完成一个绑定立即显示勾选并自动进入下一个目标。
- 记录学习历史，支持撤销上一步；冲突时保留冲突键和冲突 GPIO / 触点信息。
- 学习会话只绑定一个明确设备，结果先进入草稿，不影响其他设备运行。
- 完成后自动进入测试模式，而不是直接把用户送回技术表单。

### 7.2 测试模式

测试模式只承担验证：

- 按实体键时画布实时高亮，显示识别到的按键名称。
- 点击画布键时显示“等待实体输入”，用于验证布局和物理关系。
- 执行动作后显示短暂的“已发送 / 失败”反馈，并把完整记录写入活动。
- 提供“返回编辑”和“重新学习”两个明确出口。

学习、测试和普通运行采用不同的模式状态，避免学习期间误触发真实动作。现有 `pressedButtonIds`、`LearningTarget` 和运行事件可作为实现基础。

## 8. 活动与洞察

统计不作为首屏 KPI，而是帮助用户发现配置问题：

- 当前设备最近活动：哪个键刚刚执行了什么动作。
- 常用按键：帮助用户判断哪些键值得放到主布局或改名。
- 从未使用的按键：提示“这个键还没有被按过”，提供直接编辑入口。
- 失败动作：按设备、按键和动作类型展示，不只显示一个总错误数。
- 今日次数、七日热力图保留，但放到“活动”标签，不阻塞配置任务。

任何统计都必须保留设备 ID 归属，不能因为多个设备共享一个配置而混淆运行来源。

## 9. 可逆编辑与共享配置

自动保存继续保留，但增加四层可逆能力：

1. **短时撤销 / 重做**：动作添加、删除、排序、按键重命名、学习绑定都进入统一历史栈。
2. **配置快照**：在“数据与备份”中复制当前配置，记录时间和来源设备。
3. **恢复前预览**：导入或恢复前显示按键、动作、布局和接线的差异摘要。
4. **共享配置保护**：配置被多个设备使用时，编辑器明确提示影响范围；默认提供“复制一份，仅用于此设备”。

保存状态保持三态：保存中、已保存、保存失败。保存失败时保留草稿、允许重试，不自动回退到用户看不到的旧值。运行时继续使用最后一个已确认有效的快照，并在界面明确说明。

## 10. 视觉与文案原则

- 保留当前灰阶 + 绿色主色 token，不做大面积渐变或装饰性卡片堆叠。
- 信息层级围绕设备、按键、动作；技术字段只在异常、创客模式或 `details` 中出现。
- 状态不能只靠颜色表达：已连接、需要设置、未连接、错误均配合文字和图标。
- 正常连接状态降噪；只有“需要设置”“动作失败”“保存失败”提升到顶栏或设备行。
- 业务按钮统一使用现有 `primary-button`、`secondary-button`、`danger-button` 和 `icon-button`，图标按钮必须有可访问名称和 tooltip。
- 面向用户的文案使用任务语言：

| 默认文案 | 建议文案 |
| --- | --- |
| 设备管理 | 我的设备 |
| 按键行为 | 按键设置 |
| 配置文件 | 数据与备份（高级） |
| 就绪 | 已连接 |
| 需处理 | 需要设置 |
| 运行分配 | 正在使用 |
| 逐键学习 | 自动识别按键 |
| Hardware Profile | 接线方案（高级） |

技术名称在诊断页保留准确英文或稳定 token，不能为了本地化而把 `Command`、`Control` 等快捷键名称翻译成含义不明确的词。

## 12. 分阶段实施

### P0：验证核心方向

先做三个可点击原型或薄实现，不等待完整视觉重做：

1. **按键工作区**：新用户 30 秒内把一个键配置成“粘贴文本”。
2. **首次成功路径**：插入设备 → 选模板 → 按实体键验证，隐藏技术下拉框。
3. **逐键学习模式**：18 个键连续学习、撤销、冲突提示和完成后测试。

P0 完成条件：5 名非技术用户在没有口头提示的情况下，至少 4 人完成第一个实体按键动作；失败原因可以明确归类为“设备识别、动作配置、实体验证”三类之一。

### P1：形成可持续的编辑器

- 动作库搜索、分类、最近使用、常用模板。
- 默认只显示按下时；高级触发折叠。
- 成品模式 / 创客模式分层。
- 撤销/重做、共享配置复制、快照和恢复前差异摘要。
- 技术字段、候选错误和端口信息统一进入可展开诊断区。

### P2：提高复用和洞察

- 应用场景 Profile（例如剪辑、会议、电话终端）和可复制模板。
- 设备活动洞察、未使用按键提示、动作失败聚合。
- 应用上下文自动切换作为探索项，不在首版承诺。
- 评估 OLED / 编码器在同一动作检查器中的扩展表达。

## 14. 风险与决策

### 风险

- 自动选择 Hardware Profile 可能在多个兼容方案都有效时引发误解；必须提供“接线方案（高级）”和明确的复制/改绑动作。
- 动作库会增加右栏密度；首版限制在五类基础动作，不提前引入条件、循环和变量。
- 学习模式直接接触真实设备，必须锁定精确 `Device ID`，并在学习期间暂停该设备的普通动作执行。
- 撤销与自动保存可能产生顺序问题；历史栈必须基于已验证的编辑快照，而不是 DOM 状态。
- 共享配置复制如果没有影响范围提示，会破坏多设备独立分配的领域不变量。

### 已做出的产品决策

- 默认首页是设备工作区，不是统计仪表盘。
- 默认模式是成品模式，创客能力仍在同一个应用内按需展开。
- 默认动作触发只显示“按下时”，高级触发保留但不删除。
- 学习模式和测试模式是独立的强状态工作流，不与普通运行混用。
- 不照搬 Stream Deck 的插件商店和复杂生态，先把基础动作、模板和实体反馈做扎实。
- UI 简化不等于后端语义简化；设备身份、配置复用和 Runtime Assignment 继续由后端权威快照决定。
