# Kivo UI / 交互竞品研究

- 日期：2026-08-21
- 范围：当前 `opt/ux` 分支的 React UI、现有 UX 方案，以及可编程实体控制器/键盘配置工具的官方资料
- 目标：找可直接借鉴的 UI 模式，不做功能清单式竞品分析

## 1. Kivo 当前形态

Kivo 不是单纯的“宏键盘配置器”，而是三类产品叠在一起：

1. **消费级外设配置器**：连接设备、命名、选择配置、设置每个按键。
2. **自动化动作编辑器**：一个触发可串联粘贴、快捷键、打开目标、媒体、等待等动作。
3. **DIY 硬件工作台**：GPIO、触点矩阵、显示屏、编码器、接线学习、固件与诊断。

当前代码已经有一些很好的基础：

- 设备列表 → 可视化键盘 → 右侧动作检查器，主编辑闭环已经成立。
- 实体按键按下时，界面可实时高亮；这是很强的软硬件反馈。
- 自动保存，降低配置焦虑。
- 支持按下、释放、长按、双击及动作序列，能力明显超过普通键位映射器。
- 技术诊断字段已开始收进 `<details>`；成品设备与 DIY Profile 也已有不同分支。
- “逐键学习”可以把物理输入和界面按键关联起来，这是 Kivo 最有辨识度的交互。

### 当前主要问题

1. **用户任务和领域模型仍混在一起**  
   普通用户想做的是“让这个键粘贴一句话”，界面仍可能让他接触 Device Profile、Hardware Profile、Runtime Assignment 的影子。

2. **首次使用仍是配置选择，而不是成功体验**  
   当前 `DeviceSetupWizard` 的核心步骤仍是选择兼容 Profile，再确认名称；理想流程应以“插入 → 选用途/模板 → 按一下验证成功”结束。

3. **消费级与 Maker 级功能虽有分支，但还没有形成清楚的产品模式**  
   “按键 / 设备设置 / 按键布局 / 高级 I/O”仍处于同一层级，普通用户容易误入。

4. **动作编辑器缺少动作库入口**  
   当前以“添加动作 → 弹窗选类型”为主。动作种类扩大后，需要搜索、分类、最近使用和拖拽/点击添加。

5. **首页/统计定位不稳定**  
   README 仍描述首页统计，`HomeDashboard.tsx` 也存在，但当前 `App.tsx` 没有挂载它。说明产品 IA 已从“统计首页”转向“设备工作区”，文档尚未完全同步。对于配置工具，设备工作区应是默认首页；统计适合作为二级页，而不是抢占首屏。

6. **同一状态重复出现**  
   顶栏设备摘要、左侧设备行、设备详情都会表达连接/可用/需设置。可以减少全局状态噪音，只在异常时提升存在感。

## 2. 最值得重点拆解的产品

### 2.1 Elgato Stream Deck：主编辑器的第一参考

官方来源：

- [Explore Stream Deck](https://www.elgato.com/us/en/s/explore-stream-deck)
- [Stream Deck Profiles（官方 Marketplace）](https://marketplace.elgato.com/stream-deck/profiles)
- [Elgato Help Center](https://help.elgato.com/hc/en-us/categories/360001982811-Stream-Deck)

**与 Kivo 的相似点**

- 都是“实体按键 + 桌面配置软件 + 动作”。
- 都需要让用户理解软件中的格子和手上的实体键是一一对应的。
- 都会走向动作库、模板/Profile、应用上下文和多页配置。

**值得借鉴**

- **设备画布居中，动作库与属性检查器在侧边**：用户始终围绕实体按键工作，不围绕配置文件工作。
- **直接操作**：选中/拖入动作后立刻出现在键位上，减少多层弹窗。
- **Profile 是用户场景，不是技术对象**：直播、剪辑、会议等，比“Device Profile”更符合用户语言。
- **动作生态的可发现性**：搜索、分类、图标、插件/动作集合可以支撑功能增长。
- **文件夹/页面等容量扩展模式**：适合未来显示屏、编码器、多层按键。

**不要照搬**

- Kivo 当前动作种类有限，不要为了“像 Stream Deck”提前造插件商店。
- Stream Deck 偏重拖拽；Kivo 还必须保证键盘可达和低学习成本，应同时支持点击添加。
- Kivo 有真实接线和设备身份问题，不能隐藏到完全不可诊断。

### 2.2 Wooting Wootility：消费级设备配置与实时反馈

官方来源：

- [Wootility](https://wooting.io/wootility)
- [Wooting Help Center](https://help.wooting.io/)

**与 Kivo 的相似点**

- 都是桌面/网页式外设配置工具。
- 都需要管理设备、Profile、键位行为、固件和实时输入反馈。
- 功能本身技术性很强，但面向普通购买者。

**值得借鉴**

- **一个页面只解决一种问题**：键位、性能、灯光、Profile 分区清楚。
- **设备模型始终可见**：调整参数时，用户不会忘记当前编辑的是哪个设备/键。
- **实时可视化**：按键输入、阈值等变化立即反馈；Kivo 可把“实体按下 → UI 高亮 → 动作执行结果”做成连续反馈。
- **高级能力有解释，不直接暴露协议名**。
- **Web/桌面一致的视觉语言**，适合 Kivo 的 Tauri + React 技术形态。

**不要照搬**

- Wootility 围绕游戏键盘和模拟轴参数，信息密度较高；Kivo 普通用户不需要性能调参式面板。
- 不要把 Profile 做成横向堆叠的技术槽位，应用“用途/场景”语言。

### 2.3 ZSA Oryx：复杂键位能力的可视化表达

官方来源：

- [Oryx Configurator](https://www.zsa.io/oryx)

**与 Kivo 的相似点**

- 都是围绕一张真实键盘布局编辑每个键。
- 都有比普通按键映射更复杂的触发语义。
- 都需要在“强大”和“别吓到新用户”之间取舍。

**值得借鉴**

- **键盘布局是主导航对象**，而不是配置表格。
- **逐键检查器**：先选物理位置，再在上下文中配置行为。
- **复杂功能视觉分层**：层、长按/点按等高级行为通过局部检查器呈现，不让整张画布同时承载所有复杂度。
- **训练/验证模式**：配置后直接练习和确认键位，Kivo 可以做成“按一下刚配置的键，确认输出”。
- **版本/恢复心智**：配置工具应支持撤销或版本恢复，而不只显示“已自动保存”。

**不要照搬**

- Oryx 的层、tap dance、keycode 体系对新用户仍然偏复杂。
- Kivo 默认应只显示“按下时”，其他触发方式放进“更多触发方式”。

### 2.4 Logitech Options+：消费级 onboarding 和设备中心

官方来源：

- [Logi Options+](https://www.logitech.com/en-us/software/logi-options-plus)
- [Options+ Support](https://support.logi.com/hc/en-us/articles/4418699283607-Logi-Options)

**与 Kivo 的相似点**

- 都要管理多台实体设备。
- 都允许针对设备上的按钮配置动作。
- 都需要把固件、权限、后台运行等系统问题包装成消费者能理解的流程。

**值得借鉴**

- **设备就是首页卡片**，而不是先进入“配置文件管理”。
- **用设备示意图/热点映射按钮**，比抽象表格更贴近手里的硬件。
- **上下文说明**：选中按钮时，侧边区域解释“这个按钮当前会做什么”。
- **应用特定设置**：未来可让 Kivo 根据前台应用自动切换场景。
- **权限和后台运行以任务语言解释**，不直接展示底层系统术语。

**不要照搬**

- 高质量 3D 设备图维护成本高。Kivo 初期用 SVG/二维布局就够，避免每个 DIY 设备都要做精细资产。
- Options+ 的设备卡片适合消费硬件，但 DIY 控制器仍需要文本诊断入口。

### 2.5 VIA / Vial / Keychron Launcher：网页连接、键位测试和极简配置

官方来源：

- [VIA](https://www.caniusevia.com/)
- [VIA Documentation — Layouts](https://www.caniusevia.com/docs/layouts)
- [Vial](https://get.vial.today/)
- [Keychron Launcher](https://launcher.keychron.com/)

**与 Kivo 的相似点**

- 通过可视化布局配置实体键盘。
- 需要识别设备、映射键位、设置层/宏并写入设备或配置。
- 都有“测试这个物理键是否对应这个位置”的需求。

**值得借鉴**

- **连接后直达布局**：减少中间管理页。
- **Key Tester / Matrix Tester**：测试模式下按实体键，画布实时点亮。Kivo 已有底层能力，应把它提升成显眼功能。
- **键值分类面板**：基础键、媒体、宏、层等，适合动作库的初始信息架构。
- **网页式简洁布局**：不需要传统桌面软件的多层菜单。
- **Vial 的实时改动心智**：配置后无需显式“写入/应用”按钮，与 Kivo 自动保存吻合。

**不要照搬**

- VIA/Vial 的 keycode、层编号、矩阵概念非常工程化。
- VIA 的视觉层级和状态反馈相对弱，不适合作为 Kivo 消费级文案与 onboarding 标杆。

## 3. 其他有价值的邻近产品

### 3.1 TourBox Console

官方来源：[TourBox](https://www.tourboxtech.com/en/)

可借鉴：

- 以创作软件/使用场景组织预设，而不是以硬件配置文件组织。
- 旋钮、滚轮、按压等不同输入类型使用不同的可视表达。
- 屏幕 HUD 可提示当前控制项；这与 Kivo OLED/编码器的状态展示方向相近。

不宜照搬：TourBox 的输入器件固定，Kivo 的 DIY 拓扑更开放，不能依赖一套固定设备图。

### 3.2 Loupedeck / Razer Stream Controller

官方来源：

- [Loupedeck](https://loupedeck.com/)
- [Razer Stream Controller X](https://www.razer.com/streaming-accessories/razer-stream-controller-x)

可借鉴：

- 应用 Profile、动作分类、页面/工作区切换。
- 触屏键、旋钮、实体键混合时，用统一的动作检查器配置不同输入。
- 预设与插件降低空白画布的启动成本。

不宜照搬：产品围绕内容创作者和大量第三方集成，Kivo 当前应先把基础动作与模板做扎实。

### 3.3 Ableton Live MIDI Mapping：最值得借鉴的“学习模式”

官方来源：[Ableton Live Manual — MIDI and Key Remote Control](https://www.ableton.com/en/manual/midi-and-key-remote-control/)

可借鉴：

- 进入明确的 Mapping Mode 后，可映射目标统一高亮。
- 用户先选择软件目标，再操作硬件控件完成绑定。
- 退出 Mapping Mode 后，界面恢复正常，降低误操作风险。

对 Kivo 的直接启发：把现有“逐键学习”做成独立、强状态的全屏/大面板流程：

1. 画布高亮待学习键位；
2. 用户按实体键；
3. 键位变为已完成，并自动移动到下一个；
4. 显示 `7 / 18` 进度、撤销上一步、跳过、冲突提示；
5. 完成后进入测试模式。

### 3.4 Keyboard Maestro：动作序列编辑器

官方来源：[Keyboard Maestro](https://www.keyboardmaestro.com/main/)

可借鉴：

- 动作库可搜索、分类、收藏。
- 多动作按顺序排列，清楚显示执行流。
- 每个动作可折叠，长序列不会变成巨型表单。
- 提供可读的自然语言摘要。

不宜照搬：Keyboard Maestro 面向高级自动化用户，条件、变量、循环等概念会显著抬高 Kivo 的产品复杂度。

## 4. 建议优先级

### P0：重新定义默认工作区

默认进入：

```text
我的键盘（左） | 实体布局/按键画布（中） | 当前按键动作（右）
```

- 连接设备后直接选中它；只有多个设备时才强调设备列表。
- 正常连接状态降噪，异常状态才出现在顶栏。
- “设备设置 / 布局 / 高级 I/O”移到齿轮或高级模式，不与“按键”平级争夺注意力。

参考：Stream Deck + Wootility + Options+。

### P0：重做首次成功路径

建议流程：

1. 插上设备并自动识别；
2. 给设备起名；
3. 从用途模板选择，或从空白开始；
4. 自动选择兼容硬件配置并完成 Runtime Assignment；
5. 配置/继承一个示例键；
6. **要求用户按下该实体键，出现成功反馈后才完成 onboarding**。

不要让普通用户选择 Hardware Profile。多个兼容方案时自动选默认值，只有冲突时再询问。

参考：Options+ + Wootility + Oryx 训练模式。

### P0：把“逐键学习 + 测试”做成招牌交互

- 设置模式与测试模式分开，顶栏清楚显示当前模式。
- 使用全布局进度、当前目标、已完成标记、冲突标记。
- 实体按键和 UI 键位双向闪烁。
- 每完成一个绑定立即允许测试。

参考：Ableton MIDI Mapping + VIA Key Tester。

### P1：动作库替代纯弹窗入口

右侧动作区增加：

- 搜索；
- 分类：文字、快捷键、打开、媒体、流程；
- 最近使用；
- 常用模板；
- 点击添加和拖拽添加并存；
- 动作卡片显示自然语言摘要，可折叠编辑。

参考：Stream Deck + Keyboard Maestro。

### P1：默认只展示简单触发

- 主界面只显示“按下时”。
- “长按 / 双击 / 松开”放进“更多触发方式”。
- 启用高级触发后，再显示时间阈值。
- 毫秒改成用户语言，如“长按 0.5 秒”。

参考：Oryx 的局部高级行为；避免 VIA 的工程词汇。

### P1：正式区分“成品模式”和“创客模式”

**成品模式**：设备、按键、动作、模板、测试。  
**创客模式**：布局、GPIO、矩阵、显示屏、编码器、去抖、固件诊断。

当前代码已有 `isProductDevice` 分支，可沿这个方向做清晰的信息架构，而不是再造两套应用。

### P1：为自动保存补上“可逆性”

“已保存”只能消除保存焦虑，不能消除误改焦虑。建议增加：

- 操作后短时 Undo；
- Profile 复制/快照；
- 导入/恢复前预览差异；
- 共享配置被多个设备使用时，优先提供“为这台设备复制一份”。

参考：Oryx 的版本心智和现代编辑器的 undo 模式。

### P2：把统计降级为设备洞察

- 当前设备工作区做首页。
- 今日次数、常用按键、最近活动放入“活动/洞察”标签。
- 统计的价值应是帮助用户发现“哪个键没用、哪个键值得调整”，而不是单纯展示 KPI。

## 5. 建议先做的 3 个原型

### 原型 A：Stream Deck 式按键工作区

只验证：左设备列表、中布局、右动作库/检查器是否能让新用户 30 秒内完成一个“粘贴文本”键。

### 原型 B：首次连接到第一次成功按下

只验证：不出现 Profile/Hardware/Assignment 术语，用户能否独立完成 onboarding。

### 原型 C：逐键学习模式

只验证：18 个实体键的连续绑定、冲突修复、撤销、完成后测试。

这三个原型比继续润色统计卡片、阴影和圆角更值得优先投入。

## 6. 最终选择

如果只看 5 个产品：

1. **Elgato Stream Deck**：主编辑器结构与动作库。
2. **Wootility**：消费级设备配置、实时反馈、功能分区。
3. **ZSA Oryx**：复杂键位能力、训练与渐进披露。
4. **Logitech Options+**：多设备首页与首次连接体验。
5. **Ableton MIDI Mapping + VIA Key Tester**：逐键学习和测试模式。

一句话方向：**Kivo 应该像 Stream Deck 那样编辑，像 Options+/Wootility 那样上手，像 Ableton/VIA 那样学习和验证；而不是把自己的领域模型做得更漂亮。**
