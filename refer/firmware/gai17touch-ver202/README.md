# 丐17Touch_Ver202.hex 静态解析

分析日期：2026-09-09。输入为用户指定的 `/Users/leo/Downloads/17键/固件/丐17Touch_Ver202.hex`，不是从当前设备读取的 Flash。本次未烧录、未发送 HID 命令、未修改设备配置。

## 主要结论

此文件属于“丐17Touch”固件，其内嵌项目地址、四线按键扫描、五路触摸和单路 PWM 灯光代码相互吻合。它与仓库保存的“最丐17+4TPRO”原理图存在明确差异，不能把那份原理图的引脚表直接套到这份固件上。仅有一颗可用灯的实物描述不足以判断实物究竟采用哪一版电路。

| 项目 | 这份 HEX 的代码证据 | 17+4TPRO 原理图 |
|---|---|---|
| 扫描线 | P3.0、P3.1、P3.2、P3.3 | K1–K5，额外使用 P3.4 |
| 机械键 | 16 个扫描键 + RST 独立键 | 16 个扫描机械键 + RST 独立键 |
| 附加键 | 扫描函数未包含第五根扫描线 | 另有 S17–S20 四键 |
| 触摸 | 5 路，包含 P1.5 | 4 路，P1.5 留给 RGB |
| 灯光 | PWM2 单通道，默认 P3.4 | P1.5 单线可寻址灯链 |

## USB 身份与接口

设备描述符位于 `0x1085`，配置描述符位于 `0x1097`：

| 字段 | 值 |
|---|---|
| USB 版本 | USB 2.00，全速运行初始化 |
| VID:PID | `3062:4700`，是运行时标识，区别于 ISP 标识 |
| bcdDevice | `0x0202`，与文件名 Ver202 一致 |
| 制造商 | `画板当吃生菜`，字符串位于 `0x10DD` |
| 产品名 | `丐17Touch`，字符串位于 `0x10EB` |
| 字符串语言 ID | `0x0409` |
| EP0 最大包长 | 64 字节 |
| 配置声明最大电流 | 180 mA；是描述符声明，不是实测电流 |
| 远程唤醒 | 描述符声明支持 |

配置含两个 HID 接口，编号是 **1 和 3**，不是常见的 0 和 1。没有 CDC 串口接口。

| 接口 | 端点 | 最大包长 | 描述符轮询间隔 |
|---|---|---|---|
| 1：标准输入功能 | `0x82` IN | 64 B | 1 ms |
| 3：厂商自定义 HID | `0x84` IN | 64 B | 1 ms |
| 3：厂商自定义 HID | `0x04` OUT | 64 B | 2 ms |

USB 轮询间隔不是实测按键延迟或触摸采样率。

序列号字符串不是静态常量：`0x1572` 的函数生成 30 字节 USB 字符串描述符，内容为 **14 个大写十六进制字符**，由芯片 ID 一字节和程序空间 `0x3FFA–0x3FFF` 六字节拼成。输出缓冲区是 XDATA `0x0162`。这些出厂字节不在本 HEX 内，所以无法从文件取得这台设备的实际序列号。

## HID Report 布局

标准输入接口的报告描述符位于 `0x0F9B`，长 200 字节。下列线上的长度含 Report ID：

| Report ID | 功能 | 字节数 | 数据结构 |
|---|---|---|---|
| 1 Input | 键盘 | 9 | ID + 修饰键位图 + 保留字节 + 6 个键码 |
| 1 Output | 键盘锁定灯状态 | 2 | ID + Num/Caps/Scroll 等 5 位及填充 |
| 2 Input | 鼠标 | 5 | ID + 3 个按钮位及填充 + X + Y + 滚轮，后三项为相对有符号 8 位 |
| 3 Input | Consumer Control | 3 | ID + 16 位 Usage，用于音量、播放等；描述符允许范围 `0–0x033C` |
| 4 Input | System Multi-Axis Controller / Dial | 3 | ID + 1 位按钮 + 15 位相对角度，逻辑范围 -3600–3600 |

第 4 类报告描述了 Dial 式输入，不代表固件把原始触控条坐标作为触摸屏协议上报。报告中没有通用多点触摸屏的触点描述。

厂商接口描述符位于 `0x1063`，长 34 字节，Usage Page 为 `0xFF00`，IN/OUT 各 64 字节，没有 Report ID 项。主机库若要求额外的 Report ID 参数，应传“无 ID”的约定值，不能把它当作设备负载的命令字节。固件 `0x1F82` 会把较短的响应补零并发送完整 64 字节。

## 内置按键映射

三张表各 17 字节，表索引是固件逻辑索引，不能直接当作原理图 S 位号。`0x1A47` 为查表调用点。第一张是数字区主映射；两张备用表的选择受运行状态和 IDATA `0x9A` 的 bit7 影响，具体模式名称仍应与操作行为核对。

|---|---|---|---|
| 0 | KP 8 | KP 8 | Up |
| 1 | KP 4 | KP 4 | Left |
| 2 | KP 6 | KP 6 | Right |
| 3 | KP 2 | KP 2 | Down |

备用模式的索引 5、10 另有代码设置左 Shift 修饰位，因此实际可能是 Shift+Tab / Shift+Enter；上表只展示存储在表中的基础键码。固件还有 EEPROM 自定义映射路径，不能以三张静态表代替用户当前配置。

## 按键、触摸、灯光代码证据

- **按键**：`0x172E` 先释放 P3.0–P3.3，检查四个对地输入，再逐根拉低并读取其余三根，覆盖 4 + 4×3 = 16 个位置。`0x0CF6` 读取 `CLOCK_CFG.bit3`（RST 电平），形成另一输入。此扫描实现不能推导出 17 键任意组合无冲。
- **触摸**：`0x2551` 的通道选择表为 `02 06 05 04 03`；按 CH552 通道定义，对应 **P1.1 → P1.7 → P1.6 → P1.5 → P1.4**。`0x1E9C` 中断依次保存五路 16 位 TKEY 值，`0x1D37` 再处理这些采样。此处为扫描顺序，未确认物理空间顺序。
- **灯光**：`0x2494` 配置 `PWM_CTRL=0xC8`、`PWM_CK_SE=0x0C`；`0x2405` PWM 中断写 `PWM_DATA2`；`0x2560` 设置 `P3_MOD_OC=0xEF`，使 P3.4 适合 PWM 输出。本次识别出的灯光通路是单通道 PWM，不能据此宣称支持独立 RGB 三色或 WS2812 灯链。
- **EEPROM**：`0x2483` 读、`0x232B` 单字节写、`0x1BD1` 批量写。它们使用 ROM 控制器和逻辑 `0xC000 + 2×index` 地址，不是 HEX 中对应的普通代码段。`0x00–0x77` 被改键记录遍历，`0x78–0x7E` 有参数及校验相关代码，`0x7F` 另有状态读写。

## 厂商 HID 命令提取

`0x10FD` 处理接收缓冲区；XDATA `0x0080` 为负载起点，首字节为命令，分发表在 `0x110D`。以下来自静态反汇编，未用实物确认。偏移均从 64 字节设备负载起算。

| 命令 | 处理入口 | 可确认行为 |
|---|---|---|
| `0x01` | `0x1138` | 停止 Timer2 路径，把 byte1 写入 PWM 目标值；可作为单通道亮度控制入口，极性与感知亮度需实测 |
| `0x02` | `0x1146` | 返回 `02` + XDATA `0x0180–0x0184` 五字节通道相关值 + 当前参数（IDATA `0x7D`），其余补零；这不是五路 16 位原始 TKEY 数据 |
| `0x03` | `0x115A` | 将 byte1 限制到 5–25，更新触摸相关参数，并写 EEPROM `0x7D` 及 `0x7E` 校验值 |
| `0x04` | `0x1165` | byte2 为 1/2 时切换一个运行状态；具体 UI 含义未定 |
| `0x3F` | `0x1186` | 按 byte2 起始地址、byte3 长度，将 byte4 起的数据批量写入 EEPROM |
| `0x4F` | `0x119B` | 按 byte2 起始地址、byte3 长度读 EEPROM；响应回显前四字节，再附数据 |
| `0x50` | `0x11E3` | 改写/删除键映射；byte1 为键编号，byte2 为类型。分支处理 0、1、`0xFF`，删除分支还检查 `0xA5` |
| `0x51` | `0x11EE` | 查询 byte1 指定的键映射，响应以 `51` 开头，后接键编号、类型和映射数据 |
| `0x52` | `0x1213` | 返回改键记录区剩余空间相关值，响应 `52 value` 后补零 |
| `0x53` | `0x1231` | 从 EEPROM 重新构造运行时改键表 |
| `0xFF` | `0x1132` | 清除部分灯效运行状态并恢复 Timer2 及其中断，入口调用 `0x24F9`；与 `0x01` 的停止 Timer2 相对应 |

自定义 HID 的读参数入口有利于后续开发上位机。这里没有执行写配置、改键、亮度设置或复位命令；协议表仍需在明确目标硬件后验证，尤其是长度约束和运行状态。

`0xFF` 不是软件复位命令；本次分发表没有确认可由主机直接调用的复位命令。

## 其他字符串与数据

`0x1DF2` 有 ASCII 字符串：

```text
CMD /C "START https://oshwhub.com/yANgZEN/zui-gai-shuo-zi-jian-pan"
```

代码在 `0x16B9` / `0x1724` 引用此字符串，属于固件内的打开项目网页宏内容。本次仅提取字节，没有在电脑执行该命令。该网址以及产品字符串，是区分 Touch 与 TPRO 版本的直接证据。

`0x14D4` 等处的连续可打印字节属于数值表候选，不能全部当成用户可见文本；原始候选保存在 YAML 中。未能从 HEX 可靠恢复 C 函数名、源码注释、原始工程或完整手势状态机的语义。
