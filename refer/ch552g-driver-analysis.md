# CH552G 17 键设备驱动方案

更新日期：2026-09-09。设备范围以用户确认的实物配置为准，驱动依据为用户提供的 `丐17Touch_Ver202.hex` 静态解析。该 HEX 不是实机 Flash 读取结果，其引脚用途和 USB 描述符首先来自静态固件证据；当前实机验证进展见下段。

当日已按用户要求刷入[独立临时测试固件](../firmware/ch552g-keytest/README.md)，代码校验通过：四线扫描与 RST 路径已收到全部 17 个 ID 的按下/松开事件；五路触摸中断采样和基线校准已运行，用户完成逐键、分段滑动与长按测试后确认正常。当前 USB 为 `1209:C55C`，产品 `Kivo CH552 KeyTest`，提供键盘和 CDC；下文 `3062:4700` 仅指官方 Ver202。L1 接线、电极空间顺序与后续手势算法仍未验收。

## 当前设备范围

| 部分 | 当前依据 | 驱动范围 |
|---|---|---|
| 主控 | ISP 识别为 CH552，用户确认型号 CH552G | 独立于 ESP32-S3 / RP2040 的控制器 |
| 按键 | 用户确认 17 个；Ver202 读取 16 个扫描键和一个 RST 输入 | 17 个逻辑按键，不加入 TPRO 的四个附加键 |
| 灯光 | 用户确认大部分未焊，仅背面 L1 可用；Ver202 使用 PWM2 | 单颗 LED 的亮度、开关与状态提示；未确认 RGB 三色能力 |
| 触控条 | 用户确认一条；Ver202 顺序采集五路 TKEY | 五通道采样、校准、点击与滑动处理 |
| USB | Ver202 声明键盘、鼠标、多媒体、Dial 和厂商 HID | 优先利用现有 HID 通信 |

不从 TPRO 参考图推定本机装有 USB Hub、三个扩展口或 20 颗灯。L1 的实际驱动接线和触控电极空间顺序仍需确认。

## 按键扫描

Ver202 的 `0x172E` 扫描函数先释放 P3.0–P3.3，读取四个对地输入，然后逐根拉低并读取其余三根，共覆盖 `4 + 4 × 3 = 16` 个位置。RST 为第 17 个独立输入。

| 扫描状态 | 读取引脚 | 扫描函数中的编号 |
|---|---|---|
| 四线全部释放 | P3.0、P3.1、P3.2、P3.3 | 1、2、3、4 |
| P3.0 拉低 | P3.1、P3.2、P3.3 | 5、6、7 |
| P3.1 拉低 | P3.0、P3.2、P3.3 | 8、9、10 |
| P3.2 拉低 | P3.0、P3.1、P3.3 | 11、12、13 |
| P3.3 拉低 | P3.0、P3.1、P3.2 | 14、15、16 |

这些是扫描函数内部编号，不能直接当作参考图的 S 位号或 USB 键码。固件的三组 17 键映射已提取；逻辑键到实物键帽的位置关系需要逐键确认。

实现时只操作四根扫描线对应的 P3 位，保留 P3.4 的 PWM 和 P3.6/P3.7 的 USB 设置。释放上一根输出后再切换下一根，输入线不能推挽输出高电平。输入模式和上拉配置要在核对实物电路后确定。

RST 输入为高电平有效，读取 `CLOCK_CFG & 0x08`。要用作按键，芯片配置必须关闭该引脚的外部复位功能，普通 GPIO 初始化不能替代此配置。HEX 不包含本机实际配置位，不能据此声称该设置已完成。

初版扫描与消抖可从完整扫描周期约 1 ms、逐键稳定消抖约 5 ms 开始调试；这些是设计目标，不是本机实测结果。按下、松开以及多键组合都要验证，不能凭 HID 报告容纳六个键码便承诺扫描网络支持任意六键无冲。

## L1 灯光

实物只把背面 L1 作为可用灯。Ver202 已确认的控制路径是 PWM2：

```text
亮度目标值 → PWM_DATA2 → P3.4 默认映射 → 实际灯光驱动电路待核对 → L1
```

驱动状态用单个亮度值表达；在确认实际电路前，不定义 RGB 三字节颜色、WS2812 数据链索引或逐灯动画。需要核对 L1 与 PWM2 的连接、是否经过开关管，以及占空比与亮度的极性。固件有 `PWM_CTRL=0xC8` 的极性配置，不能假定数值越大实物越亮。

沿用官方固件时，可基于厂商 HID 的 `0x01` 命令设置 PWM 目标值。该命令会停止 Timer2 路径；`0xFF` 则清除部分灯效状态并恢复 Timer2，不是复位命令。二者的灯效切换表现尚未实机验证，完整静态协议见 [命令表](firmware/gai17touch-ver202/README.md#厂商-hid-命令提取)。

重新实现固件时优先用硬件 PWM 输出，在主循环更新亮度或呼吸曲线，无需为 WS2812 连续发送灯帧。因此不沿用 TPRO 灯链的 SPI 编码、整帧屏蔽中断或触摸避让方案。

## 触控条

Ver202 在 `0x2551` 保存通道选择表 `02 06 05 04 03`，对应 TIN1、TIN5、TIN4、TIN3、TIN2。P1.5 属于触摸采样，不应配置为灯链输出。这是采样顺序，不是触控条上的上下排列顺序。

`0x1E9C` 的触摸中断保存五路 16 位原始值，`0x1D37` 处理采样。对新的驱动实现，建议按以下链路组织：

```text
五路原始采样 → 基线与噪声处理 → 位置估计 → 点击/长按/滑动 → HID 或 Kivo 动作
```

先确认电极顺序、各通道响应方向和增益，再确定位置算法。不能从通道编号直接给出空间坐标，也不能把五通道等同于通用多点触摸屏。完整手势状态机尚未从 HEX 恢复；原固件输出的是鼠标、Consumer Control、Dial 等报告，不是标准触摸屏触点报告。

厂商 HID `0x02` 返回五个**单字节通道相关值**和一个当前参数，不能把它误标为五路 16 位原始 TKEY 数据。`0x03` 修改触摸相关参数并写 EEPROM，值被限制在 5–25；其实际灵敏度方向需要验证。

实现采样时保留 P1.1/P1.4/P1.5/P1.6/P1.7 的触摸输入用途。若使用 ch55xduino 的 TIN 位掩码接口，TIN1–TIN5 对应 `0x3E`；它不同于硬件通道选择寄存器中的 2、6、5、4、3，不能混用。

## USB 与 Kivo

Ver202 声明运行时 VID/PID `3062:4700`，产品名 `丐17Touch`，接口 1 为标准输入 HID，接口 3 为厂商 HID。接口 3 使用 `0x84` IN 和 `0x04` OUT，各 64 字节，无 Report ID 项；没有 CDC 串口。这些标识描述官方程序；当前临时固件的实机身份见本文开头。

建议先沿用现有固件验证 HID 识别、输入和配置读取，评估桌面端适配范围；不要默认必须先重写固件。若需 Kivo 专用事件、可控的去抖或新的手势算法，再建立独立的 C + SDCC 固件目标，使用静态缓冲区和固定板级扫描。

当前 Kivo 的 ESP32-S3 / RP2040 通用固件依赖 C++ 容器和动态拓扑；[输入拓扑](../lib/gpio_trigger/src/InputTopology.h)的独立 rows/columns 不能直接表示这里四线复用扫描。[平台接口](../firmware/src/platform/Platform.h)和[控制器划分](../docs/adr/0001-separate-controller-families-from-board-profiles.md)可作为桌面适配边界参考，现有固件不能只增加引脚 YAML 就在 CH552G 上运行。
